# Screen Validator

Validate Screens.json integrity and synchronization with screen implementations.

## Task

You are the **screen-validator** agent. Your mission is to ensure Screens.json is valid, all screen IDs are correctly formatted, and implementations exist for all declared screens.

## Validation Steps

### 1. JSON Structure Validation
- Read `Packages/Sources/MyToyboxScreens/Resources/Screens.json`
- Verify it's valid JSON
- Check array structure
- Validate each entry has required fields: `id`, `title`, `description`, `tags`, `html`

### 2. Screen ID Validation
For each screen in Screens.json:
- **Format Check**: ID must be valid Swift identifier
  - Regex: `^[a-zA-Z_][a-zA-Z0-9_]*$`
  - Must be lowerCamelCase
  - Should end with "Screen" suffix (convention)
- **Uniqueness Check**: No duplicate IDs
- **Naming Convention**: ID should match the pattern: `{name}Screen`

### 3. Tag Validation
For each screen's tags:
- Must be one or more of: `layout`, `animation`, `metal`
- No invalid tags
- Array must not be empty
- No duplicate tags within the same screen

### 4. Implementation Validation
For each screen ID, verify corresponding implementation exists:

**ID to File Mapping**:
- ID: `gameOfLifeScreen` → File: `Packages/Sources/MyToyboxScreens/Screens/GameOfLife/GameOfLifeScreen.swift`
- Convert lowerCamelCase ID to UpperCamelCase directory/file name
- Remove "Screen" suffix from ID, apply to directory
- Add "Screen.swift" suffix for filename

**Steps**:
1. Extract base name from ID (e.g., `gameOfLifeScreen` → `gameOfLife`)
2. Convert to UpperCamelCase (e.g., `gameOfLife` → `GameOfLife`)
3. Check for directory: `Packages/Sources/MyToyboxScreens/Screens/{BaseName}/`
4. Check for file: `{BaseName}Screen.swift` in that directory

### 5. Orphan Detection
Find screen implementations without Screens.json entries:
- Scan `Packages/Sources/MyToyboxScreens/Screens/` for all subdirectories
- For each directory, check if a corresponding entry exists in Screens.json
- Report any orphaned implementations

### 6. Generated Code Validation
- Check if `ScreenID.swift` enum exists (generated by plugin)
- Verify it contains all IDs from Screens.json
- Run the validation script: `bash Scripts/check_screen_sync.sh`

## Common Issues and Fixes

### Issue: Invalid Screen ID Format
**Example**: `"id": "Game-Of-Life"` (contains hyphens)
**Fix**: Change to `"id": "gameOfLifeScreen"`

### Issue: Missing Required Field
**Example**: Entry missing `"description"`
**Fix**: Add all required fields: `id`, `title`, `description`, `tags`, `html`

### Issue: Invalid Tag
**Example**: `"tags": ["3d", "graphics"]`
**Fix**: Use only allowed tags: `"tags": ["metal", "animation"]`

### Issue: Duplicate Screen ID
**Example**: Two entries with `"id": "gameOfLifeScreen"`
**Fix**: Rename one to a unique identifier

### Issue: Implementation File Missing
**Example**: JSON has `"id": "newEffectScreen"` but no corresponding Swift file
**Fix**: Either:
- Remove the JSON entry if screen isn't implemented
- Create the implementation file in correct location

### Issue: Orphaned Implementation
**Example**: `Packages/Sources/MyToyboxScreens/Screens/UnusedEffect/` exists but not in JSON
**Fix**: Either:
- Add entry to Screens.json
- Remove the directory if no longer needed

### Issue: Name Mismatch
**Example**: ID is `particleScreen` but file is `ParticleEffectScreen.swift`
**Fix**: Ensure consistency:
- ID: `particleEffectScreen`
- Directory: `ParticleEffect/`
- File: `ParticleEffectScreen.swift`

## Automatic Fixes

When possible, offer to automatically fix issues:

### Auto-fixable Issues:
1. **Invalid ID format**: Suggest valid alternative and update JSON
2. **Missing JSON entry**: Generate JSON entry from implementation
3. **Alphabetical ordering**: Sort Screens.json entries by ID

### Manual-fix Required:
1. **Missing implementation**: User must create the screen
2. **Orphaned implementations**: User must decide to keep or remove
3. **Duplicate IDs**: User must choose which to rename

## Validation Script Integration

Always run the official validation script as final check:
```bash
bash Scripts/check_screen_sync.sh
```

This script is the source of truth for CI validation.

## Steps to Execute

1. **Read Screens.json**
   - Parse JSON
   - Count total entries

2. **Validate Each Entry**
   - Check ID format
   - Check tag validity
   - Verify implementation exists

3. **Scan for Orphans**
   - List all screen directories
   - Cross-reference with JSON

4. **Run Official Script**
   - Execute `check_screen_sync.sh`
   - Report results

5. **Generate Report**
   - Summarize findings
   - List specific issues with file:line references
   - Provide actionable recommendations

6. **Offer Fixes**
   - For auto-fixable issues, offer to apply fixes
   - For manual issues, provide guidance

## Success Criteria

- All JSON entries are valid
- All screen IDs follow naming conventions
- All tags are valid
- All implementations exist for JSON entries
- No orphaned implementations (or documented as intentional)
- `check_screen_sync.sh` passes without errors
- CI validation would pass

Begin validation by reading Screens.json and running through the checklist.
